## Projects

### 🧠 RAG AI System — 92% Answer Accuracy
`FastAPI` `FAISS` `LLMs` `Semantic Search` `PostgreSQL`

Document-heavy workflows had no intelligent retrieval layer — searching large PDF and structured file collections was manual, slow, and error-prone.

Built a full RAG pipeline from scratch: custom chunking, FAISS vector embeddings, semantic retrieval, and LLM-driven answer synthesis via a FastAPI backend. Tuned iteratively against real queries across diverse document types.

**Result:** 92% answer accuracy in production, handling 1,000+ queries daily. Manual document lookup was eliminated entirely.

> *What this means for you: If your team wastes hours searching documents, this is solved.*

---

### ⚡ Backend Query Optimization — 77% Faster
`PostgreSQL` `FastAPI` `Query Optimization` `Backend Architecture`

A transactional backend was suffering from slow API responses under load — queries took seconds to return, causing timeouts on data-heavy endpoints.

Profiled every slow query with `EXPLAIN ANALYZE`, restructured missing indexes, rewrote N+1 patterns, added a caching layer, and converted critical ORM calls to optimized raw SQL.

**Result:** 77% reduction in query execution time. Endpoints that timed out under load now respond within target latency — and have held under scaling.

> *What this means for you: If your API slows down as traffic grows, this is fixable.*

---

### 🎨 GenAI Image Pipeline — 30% Faster Inference
`PyTorch` `ONNX` `HuggingFace` `Model Optimization` `Google Cloud`

A generative image pipeline was too slow and too expensive to run at scale — high inference latency, poor GPU utilization, and growing compute costs.

Applied INT8 quantization, dynamic batching, and ONNX export for runtime acceleration. Profiled GPU memory allocation, parallelized pipeline stages, and removed redundant preprocessing.

**Result:** 30% reduction in inference latency. Compute costs dropped proportionally with no degradation in output quality.

> *What this means for you: AI features don't have to be expensive to run.*

---

### 📱 Flutter Finance App — 25% Faster Load Time
`Flutter` `BLoC` `Clean Architecture` `WebSockets` `Dart`

A real-time financial analytics app had sluggish startup, messy state management, and a codebase too fragile to extend safely.

Re-architected the app with BLoC for predictable state, introduced lazy loading and widget-level caching, eliminated unnecessary rebuilds, and replaced polling with WebSocket connections.

**Result:** 25% faster load times, sub-second real-time updates, and a modular codebase — shipped across iOS, Android, and Web from a single repo.

> *What this means for you: A well-built Flutter app is faster to ship and cheaper to maintain.*
